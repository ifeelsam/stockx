| 2026-11-24 | `spl` feature of `ephemeral-rollups-sdk` re-tested on Anchor 1.2.2: **still unsupported**, stays off | With `spl`, SBF build fails on both v0 and v3 with "overflows the maximum allowed frame space" in `curve25519_dalek` / `solana_ed25519` (solana-sdk crypto linked into the program). Without it the build is clean. Retest when the SDK moves `solana-sdk` behind a non-program feature |
| 2026-11-24 | `PriceFeed` gets an extra `max_move_bps` field; band for Path B is enforced in `push_price` against the feed's own previous price | `push_price` has no `Series` account; spec fields otherwise unchanged |
| 2026-11-24 | `Series.last_price` stays on the (non-delegated, read-only on ER) `Series`; Path A band reference will live in the delegated `Stats` account | The ER cannot write `Series`, so a band reference stored there would never update |
| 2026-11-24 | `card.shares` holds the *worst-case reservation* while `RandomnessPending`, and the actual win after reveal | Gives `cancel_pending`/callback the exact amount to release without an extra field; reservation = `max_multiplier × ticket ÷ locked_price` per card |
| 2026-11-24 | `vrf_request_id` = sha256(player, card_id, caller_seed, i); passed to the callback as `callback_args` (card_id, request_id). Callback looks up by (id, request_id) and requires `RandomnessPending` | VRF doesn't expose a request id. Cancel zeroes the id, a reused slot has a new id, so late/duplicate callbacks fail with `VrfRequestMismatch` / `AlreadyRevealed` |
| 2026-11-24 | Share unit = 6 decimals (`STOCK_DECIMALS`), enforced in `create_series`; `shares = mult × ticket_e6 × 1e8 ÷ price_e8` | Keeps all mock stock mints uniform and the math in one pure function (`shares_for`) |
| 2026-11-24 | `undelegate_player` refuses while any card is Paid/RandomnessPending/ClaimRequested | A VRF callback or payout needs the account on the rollup |
| 2026-11-24 | Cargo feature `localnet` accepts `DEFAULT_EPHEMERAL_TEST_QUEUE` in `buy_card`; production builds accept only `DEFAULT_EPHEMERAL_QUEUE` | MagicSVM/local stack use test queues |
| 2026-11-24 | `VrfCallback` declares `vrf_program_identity` itself, with a compile-time `const` address, instead of letting `#[vrf_callback]` inject it | The macro derives the scoped identity PDA at **runtime** (const fn evaluated in non-const context incl. a curve check), which exhausts the 197k CU callback budget before any program code runs (`exceeded CUs meter`). Same check, evaluated at compile time. Covered by `spoofed_callback_cannot_pick_the_outcome` |
| 2026-11-24 | MagicSVM tests live in `tests/magicsvm` (standalone workspace) and run with `cargo +1.93.0 test` after `anchor build --arch v0` | `magicblock-litesvm`/`solana-syscalls 4.2.2` need Rust ≥ 1.93; stable on this machine was 1.92. Installed 1.93.0 side-by-side (default untouched) |
| 2026-11-24 | Pyth feed ids: TSLA `16dad506…32f1` (Equity.US.TSLA/USD), NVDA `b1073854…a593` (Equity.US.NVDA/USD), SOL `ef0d8b6f…b56d` (Crypto.SOL/USD); all `expo -8` stored on our feeds | Looked up via Hermes `/v2/price_feeds`. Hermes `/v2/updates/price/*` returns 401 without auth as of 2026-11-24, so the keeper price source must be pluggable (key-authenticated Hermes, or other) |
| 2026-11-24 | `fund_vault` is a plain SPL transfer into the vault's ATA (done in the setup script), plus `sync_inventory` on the rollup | No program logic needed for the transfer; the mirror credit is admin/keeper-gated |
| 2026-11-24 | Demo series (id 4) shares the mTSLA vault with series 1, jackpot weight 5,000/100,000 (1 in 20) | Vault is per stock mint; demo odds are labelled DEMO ODDS in the UI and never mixed into the public prize table |
| 2026-11-24 | Deployer/keeper/mint keypairs live in `~/.config/stockx/` (0600), never in the repo | Plan §0.5 / §13: no secrets in git |
| 2026-11-24 | Settlement: `claim_all(series_id)` claims ≤ 8 revealed cards of **one series** per call; Player PDA is payer, escrow authority and committed account (PDA-signed, `magic_fee_vault` from the delegation record's validator) | Vault accounting is per stock mint; 8 actions ≈ 2.7 KB of CPI data, safely under the 10 KB limit. The UI loops for more. Commits use the fee-vault path so the 10-commit cap doesn't apply |
| 2026-11-24 | `pay_out` is two thin entrypoints over one `settle()`: `pay_out_action` (`#[action]`, requires the delegation program's escrow signature, `escrow_auth == player`) and `pay_out` (keeper-signed) | Per MagicBlock guidance: action handlers must authenticate the caller; the keeper needs a direct repair path. Exactly-once is the `Payout` PDA (`ts != 0` → `AlreadyPaid`) |
| 2026-11-24 | Post-commit action rent (Payout receipt, ~0.0011 SOL/card) is paid from the player's action **escrow** (`topUpActionEscrowIx`, base-layer, index 255); `signup` also moves 0.01 SOL onto the Player PDA for its own commit fees | Escrow is the documented rent payer for actions; the PDA pays `magic_fee_vault` charges from the 26th commit |
| 2026-11-24 | `settle()` reads the committed Player in place (`bytemuck::try_from_bytes`), never by value | A by-value 3.6 KB `Player` overflows the 4 KB BPF stack frame (caught by the SBF build) |
| 2026-11-24 | MagicSVM runs post-commit actions atomically (a failing action rolls the whole claim back); a real validator lands the commit and drops the action. The "dropped action → keeper repair → AlreadyPaid" test reconstructs the post-failure base state instead | MagicSVM cannot produce "commit landed, action dropped". **Must be re-verified on devnet** (DEPLOYMENTS/PROGRESS checklist) |
| 2026-11-24 | **Session spend cap is enforced in program logic** (`session_spend_remaining_e6`), not via SPL `approve`. USDC custody: users hold eSPL on the rollup; `deposit_usdc` moves it to a treasury token account owned by the **Config PDA** and credits `Player.usdc_balance_e6`; `withdraw_usdc` (owner only) pays back via PDA-signed transfer | The session key never owns the eSPL account and can only decrement the ledger within its cap. A PDA-owned treasury lets the program sign refunds/withdrawals without a keeper. The treasury ATA must be created on the rollup as a Magic ATA (no owner signature needed); this is validated on devnet, MagicSVM tests stand in with delegated token accounts |
| 2026-11-24 | Web app runs a **mock backend** (`apps/web/lib/game.tsx`, `NEXT_PUBLIC_BACKEND=mock`) that simulates buy → VRF reveal → claim → portfolio in-browser, using the real SDK `cardArt`/`tierFor`/`sharesFor` | Nothing is deployed to devnet yet (deployer has 0 SOL). Plan Day 2 explicitly allows scratch UIs on mock data. The chain backend plugs in behind the same `useGame()` shape; pages don't change |

| 2026-11-24 | **`sell_to_vault` is a single base-layer instruction** against a keeper-posted `SellQuote` (["quote", stock_mint], never delegated): shares user→vault ATA, USDC pool (ATA of Config PDA) → user ATA, 90 s quote TTL, 50 bps spread, `min_usdc_e6` slippage guard. USDC lands in the user's **base-layer** wallet (they `deposit_usdc` again to play) instead of being credited on the rollup as the plan sketched | Stock lives on Solana and the rollup `PriceFeed` is delegated (its base copy is stale), so a rollup-credited sale would need cross-layer messaging and a nonce protocol with no atomicity. | 2026-11-24 | Sold shares reach the rollup inventory mirror via keeper `ack_sold` (base) **then** `sync_inventory` (rollup) | A crash between the two under-counts inventory (safe) rather than double-counting. Quote init uses ts=1 so sells stay paused until the keeper posts a real price and the first update is not band-limited; band (10%) applies only while the previous quote is < 1 h old |
| 2026-11-24 | SDK `sell()` has two backends: `devnetVault` (default) and `paymentsApi` (`/v1/swap/quote` → `/v1/swap/swap`, public visibility), the latter implemented and typed but refused on devnet | Plan §3 swaps rule; request shape follows the skill's private-payments reference. Not exercised against the live API (mainnet only) |

| 2026-11-24 | Path A max-move band is stored in **`VaultState.last_oracle_price/ts`** (delegated, writable on the rollup), not `Series.last_price` (Series is a base-layer account and not writable in the ER). A band against a stale baseline would wedge sales forever after any gap, so old baselines reset (the oracle itself stays trusted). `Series.last_price` is now unused by the program |
