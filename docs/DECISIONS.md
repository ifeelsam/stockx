# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-11-24 | Price source defaults to Path B (self-pushed) for equities | MagicBlock oracle feed list is crypto-only; awaiting their answer |
| 2026-11-24 | Anchor CLI/lib **1.0.2** (exact `=1.0.2`, all `anchor-*` sub-crates pinned in Cargo.lock) + `ephemeral-rollups-sdk =0.18.0` feature `anchor` | SDK `anchor` feature = Anchor 1.x. Without exact pins `anchor-lang` floats to 1.2.2 and macro crates mismatch (`create_account_allow_prefund` missing). Re-pin with `cargo update -p <crate> --precise 1.0.2` if the lock is regenerated |
| 2026-11-24 | SDK features `anchor,vrf` only; `spl` **dropped** from the program crate | `spl` pulls a host-side `solana-sdk` tree with duplicate `solana-message` (2.4/3.1) that fails to build for SBF. eSPL on the rollup shows up as a plain SPL token account (SDK lifecycle model), so plain SPL CPI is enough; client SDK handles eSPL deposit/withdraw. Revisit if we need `ephemeral-spl-api` CPI |
| 2026-11-24 | `getrandom` 0.3 stub backend for SBF (`.cargo/config.toml` cfg + `__getrandom_v03_custom` in lib.rs) | `solana-address` enables `rand`; nothing calls it on-chain |
| 2026-11-24 | `Player` is `#[account(zero_copy)]` (3.6 KB, 112-byte `Card`, no implicit padding) | Borsh deserialization of 3.5 KB blows the 4 KB BPF stack; also keeps it far under the 10,240-byte commit limit (unit-tested) |
| 2026-11-24 | Moved to **Anchor 1.2.2** (CLI via avm, `anchor-*` crates `=1.2.2`) and build with `anchor build --arch v0` | 1.2.2 CLI defaults to platform-tools v1.57 + SBPF **v3** (target `sbpfv3-solana-solana`). v0 keeps the ER validator-safe, known target and the `.cargo/config.toml` getrandom cfg. Always pass `--arch v0` |
| 2026-11-24 | `spl` feature of `ephemeral-rollups-sdk` re-tested on Anchor 1.2.2: **still unsupported**, stays off | With `spl`, SBF build fails on both v0 and v3 with "overflows the maximum allowed frame space" in `curve25519_dalek` / `solana_ed25519` (solana-sdk crypto linked into the program). Without it the build is clean. Retest when the SDK moves `solana-sdk` behind a non-program feature |
| 2026-11-24 | `PriceFeed` gets an extra `max_move_bps` field; band for Path B is enforced in `push_price` against the feed's own previous price | `push_price` has no `Series` account; spec fields otherwise unchanged |
| 2026-11-24 | `Series.last_price` stays on the (non-delegated, read-only on ER) `Series`; Path A band reference will live in the delegated `Stats` account | The ER cannot write `Series`, so a band reference stored there would never update |
| 2026-11-24 | `card.shares` holds the *worst-case reservation* while `RandomnessPending`, and the actual win after reveal | Gives `cancel_pending`/callback the exact amount to release without an extra field; reservation = `max_multiplier × ticket ÷ locked_price` per card |
| 2026-11-24 | `vrf_request_id` = sha256(player, card_id, caller_seed, i); passed to the callback as `callback_args` (card_id, request_id). Callback looks up by (id, request_id) and requires `RandomnessPending` | VRF doesn't expose a request id. Cancel zeroes the id, a reused slot has a new id, so late/duplicate callbacks fail with `VrfRequestMismatch` / `AlreadyRevealed` |
| 2026-11-24 | Share unit = 6 decimals (`STOCK_DECIMALS`), enforced in `create_series`; `shares = mult × ticket_e6 × 1e8 ÷ price_e8` | Keeps all mock stock mints uniform and the math in one pure function (`shares_for`) |
| 2026-11-24 | `undelegate_player` refuses while any card is Paid/RandomnessPending/ClaimRequested | A VRF callback or payout needs the account on the rollup |
| 2026-11-24 | Cargo feature `localnet` accepts `DEFAULT_EPHEMERAL_TEST_QUEUE` in `buy_card`; production builds accept only `DEFAULT_EPHEMERAL_QUEUE` | MagicSVM/local stack use test queues |
| 2026-11-24 | `VrfCallback` declares `vrf_program_identity` itself, with a compile-time `const` address, instead of letting `#[vrf_callback]` inject it | The macro derives the scoped identity PDA at **runtime** (const fn evaluated in non-const context incl. a curve check), which exhausts the 197k CU callback budget before any program code runs (`exceeded CUs meter`). Same check, evaluated at compile time. Covered by `spoofed_callback_cannot_pick_the_outcome` |
| 2026-11-24 | MagicSVM tests live in `tests/magicsvm` (standalone workspace) and run with `cargo +1.93.0 test` after `anchor build --arch v0` | `magicblock-litesvm`/`solana-syscalls 4.2.2` need Rust ≥ 1.93; stable on this machine was 1.92. Installed 1.93.0 side-by-side (default untouched) |
